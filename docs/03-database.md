ข้อมูลทั้งหมดเก็บใน **Supabase** (ฐานข้อมูล PostgreSQL บนเน็ต) ไฟล์สร้างตารางอยู่ที่ `supabase/sql/`

| ไฟล์ | สร้างอะไร |
|---|---|
| `001_start.sql` | ตาราง `groups`, `notes`, `tasks` + กฎความปลอดภัย + เปิดอัปเดตสด |
| `002_files.sql` | ถังเก็บไฟล์ `user-files` + ตาราง `files` |

> รันซ้ำได้ ไม่พัง (ใช้ `if not exists` / `drop ... if exists`)
> **เพิ่มตารางใหม่:** สร้างไฟล์เลขถัดไป เช่น `003_diary.sql` แล้วไปรันใน SQL Editor

## ตาราง `groups` (หมวดหมู่)
ใช้ร่วมกันทั้งไอเดียและงาน

| คอลัมน์ | ชนิด | ความหมาย |
|---|---|---|
| `id` | uuid | รหัส (สร้างให้อัตโนมัติ) |
| `user_id` | uuid | เจ้าของ (ใส่ให้อัตโนมัติจากคนที่ล็อกอิน) |
| `name` | text | ชื่อหมวด |
| `emoji` | text | อีโมจิหน้าชื่อ |
| `color` | text | สีประจำหมวด เช่น `#F2BFC8` |
| `cover_picture` | text | ภาพปก: `pattern:hearts` (ลายสำเร็จรูป) หรือ path ไฟล์ที่อัปโหลด |
| `order_number` | integer | ลำดับ (น้อยอยู่ก่อน) |
| `created_at` | timestamptz | เวลาที่สร้าง |

## ตาราง `notes` (ไอเดีย)

| คอลัมน์ | ชนิด | ความหมาย |
|---|---|---|
| `id`, `user_id`, `created_at` | | เหมือนด้านบน |
| `title` | text | หัวข้อ |
| `content` | jsonb | เนื้อหาเต็ม (รูปแบบ JSON ของ TipTap มีรูป/วิดีโออยู่ในนี้) |
| `plain_text` | text | เนื้อหาแบบตัวหนังสือล้วน ใช้ค้นหา + โชว์ตัวอย่าง |
| `first_picture` | text | path รูปแรก ใช้ทำรูปย่อในหน้ารายการ |
| `group_id` | uuid | อยู่หมวดไหน (ว่าง = ไม่มีหมวด) |
| `is_pinned` | boolean | ปักหมุดไหม |
| `updated_at` | timestamptz | แก้ล่าสุดเมื่อไหร่ (อัปเดตเองอัตโนมัติ) |
| `deleted_at` | timestamptz | เวลาที่ย้ายไปถังขยะ (**ว่าง = ยังไม่ถูกลบ**) |

## ตาราง `tasks` (สิ่งที่ต้องทำ)

| คอลัมน์ | ชนิด | ความหมาย |
|---|---|---|
| `text` | text | ข้อความงาน |
| `is_done` | boolean | เสร็จหรือยัง |
| `importance` | text | `low` = ต่ำ, `medium` = กลาง, `high` = สูง |
| `due_date` | date | วันกำหนดส่ง (ว่างได้) |
| `group_id` | uuid | อยู่หมวดไหน |
| `done_at` | timestamptz | เวลาที่ติ๊กเสร็จ |
| `updated_at`, `deleted_at` | | เหมือนตาราง notes |

## ตาราง `files` (ข้อมูลไฟล์ที่อัปโหลด)
ตัวไฟล์จริงอยู่ใน Storage ส่วนตารางนี้จดว่า "ไฟล์ไหนเป็นของอะไร"

| คอลัมน์ | ความหมาย |
|---|---|
| `belongs_to_type` | ไฟล์เป็นของอะไร: `note`, `group` (ระบบใหม่ใส่ชื่อตัวเองได้) |
| `belongs_to_id` | id ของเจ้าของ เช่น id ของโน๊ต |
| `file_path` | ตำแหน่งไฟล์ใน Storage |
| `file_type` | ชนิดไฟล์ เช่น `image/jpeg`, `video/mp4` |
| `file_size` | ขนาด (byte) |
| `width`, `height` | ขนาดรูป (ถ้าเป็นรูป) |

## 🔗 ความสัมพันธ์

```
groups ──┬── notes.group_id   (ลบหมวด → โน๊ตกลายเป็น "ไม่มีหมวด" ไม่หายไปด้วย)
         └── tasks.group_id   (เหมือนกัน)

notes ───── files (belongs_to_type = 'note', belongs_to_id = notes.id)
groups ──── files (belongs_to_type = 'group' ใช้กับภาพปกที่อัปโหลด)
```

## 🔒 ความปลอดภัย (RLS)

ทุกตารางเปิด **Row Level Security** กฎคือ
```sql
user_id = auth.uid()   -- เห็น/แก้ได้เฉพาะแถวที่เป็นของตัวเอง
```
ไฟล์ใน Storage ก็เหมือนกัน: เปิดได้เฉพาะไฟล์ในโฟลเดอร์ชื่อ `user_id` ของตัวเอง
→ ถึงจะมีหลายคนใช้เว็บเดียวกัน ก็ไม่มีใครเห็นข้อมูลคนอื่น

## 🗑️ ถังขยะ + ลบอัตโนมัติ 30 วัน

1. **กดลบ** = ไม่ได้ลบจริง แค่ใส่เวลาใน `deleted_at` (เรียกว่า soft delete)
2. หน้าปกติจะดึงเฉพาะแถวที่ `deleted_at` ว่าง
3. หน้าถังขยะดึงแถวที่ `deleted_at` ไม่ว่าง แล้วนับวันที่เหลือ
4. **กู้คืน** = ล้าง `deleted_at` ให้ว่าง
5. **ลบถาวร** = ลบไฟล์ที่แนบใน Storage ก่อน แล้วค่อยลบแถว
6. **ทุกครั้งที่เปิดแอพ** `deleteOldTrash()` (ไฟล์ `src/features/trash/deleteOldTrash.ts`) จะลบถาวรของที่อยู่ในถังเกิน 30 วัน

> ทำไมไม่ตั้งเวลาลบในฐานข้อมูล (pg_cron)?
> เพราะ SQL ลบไฟล์ใน Storage ไม่ได้ ถ้าลบแค่แถว ไฟล์รูป/วิดีโอจะค้างกินพื้นที่
> **เปลี่ยนจำนวนวัน:** แก้ `TRASH_KEEP_DAYS` ใน `deleteOldTrash.ts`

## 🛠️ ดูข้อมูลตรงๆ ใน Supabase
เมนู **Table Editor** > เลือกตาราง จะเห็นข้อมูลทั้งหมด แก้ไขได้ (ระวังลบผิด)

### ทดสอบการลบอัตโนมัติ 30 วัน
ใน SQL Editor รัน (เปลี่ยนโน๊ตในถังขยะให้เหมือนลบไป 31 วันแล้ว)
```sql
update notes set deleted_at = now() - interval '31 days' where deleted_at is not null;
```
แล้วรีเฟรชเว็บ → โน๊ตเหล่านั้นต้องหายไปจากถังขยะ
